## 一、为什么下线"应用内登录教务读取课表"

早期做过 `ui/webimport`：内嵌 WebView 打开学校门户，用户在里面登录，再把课表读出来。

放弃的原因有三条，缺一不可：

1. 门户是 SPA，WebView 里渲染不稳定，注入脚本随学校前端改版反复失效。
2. 需要用户在**第三方容器**里输入学校密码——收益与风险完全不成比例。
3. 教务导出的文件解析已被真实导出件验证可用，是更稳的路径。

结论：**只支持文件导入与手动录入**，不碰学校账号。这条至今没变，也是本项目
"不登录、不采集"定位的来源。

## 二、课表导入：为什么只保留两种入口

- **文件**（`.xlsx` / `.xlsm` / `.docx` / RTF 编码的 `.doc`）：自研解析，不引第三方库；
  旧版**二进制** `.doc` 会提示另存为 `.docx`——二进制格式解析的投入产出比太低。
- **手动录入**：`weekMask` 用位图存周次，手动录入与导入走同一套入库逻辑。

曾经支持的纯文本粘贴、`.txt`/`.csv`/`.html` 导入都已移除：格式太多，每种都要独立测试，
而实际使用中九成是教务导出的 Excel/Word。

## 三、资讯抓取的现实约束

- **正文容器靠启发式**：按站点模板依次尝试 `#vsb_content` → `div.v_news_content` →
  `.conlis .cen` → `.conlis` → `article`。换模板就会失配，所以顺序不能随意调整。
- **图片要过滤**：排除 `cenr/side/right/recommend/footer` 等噪声容器、宽≤160 或高≤80 的小图、
  以及非 `/__local/` 却含 `/images/` 的模板图。不过滤会抓到整排侧栏横幅。
- **分页不是时序**：`/ndyw/2.htm` 会返回 2005 年的内容。因此开学时间识别**只在栏目首页**找线索，
  不能靠翻页回溯。

## 四、开学时间为什么保留手动入口

自动识别（抓「开学/开课/校历」类文章，从正文或发布日期推断第一周周一）在学期开始时有效，
但学期开始距今较远时线索会沉到分页深处，识别不到。

所以设计成：**手动改过就标记 `manual`，自动结果不再覆盖**；想重新识别就再点一次「自动识别」。
这是"自动优先但不强加"的折中。

## 五、校历为什么是人工结构化

校历以**通知或图片**形式发布，没有可机读接口，爬虫只能拿到一句"详见附件"。

做法：人工结构化进资源包（`calendar/<school>_calendar.json`），每年两次维护；
`verified` 字段标记是否已与教务处原文核对，未核对的学年在页脚红字提示。

## 六、滑动性能：四条措施（仍然有效）

课表左右滑动是唯一的高频动画路径。

| 措施 | 说明 |
|---|---|
| 无嵌套滚动 | 课表铺满一屏，行高按可用高度反算（30–64dp），去掉 `verticalScroll` 包裹分页 |
| 绘制取代布局 | 网格线 `drawBehind` 一次画完；课程块由单个 `Layout` 统一 `place`；边框自绘 |
| 文案预计算 | 时间区间、周次标签在数据变化时算好，绘制阶段只读字段 |
| 文字节点合并 | 每块从 5 个 `Text` 合并为 2 个；单页文字节点约 140 → 60 |

**动效规格**：统一 `MotionSpecs.Decelerate = cubic-bezier(0.05, 0.7, 0.1, 1)`（起步即最大速度）；
Pager 吸附用 `tween(280)` 而不用默认 `spring()`（弹簧从 0 速起步，观感像"先加速"）。

**尺寸外置**：列宽/行高在分页外算一次传入，每页不再各带 `BoxWithConstraints`（SubcomposeLayout）。

**帧率声明**：`MainActivity` 通过 `preferredDisplayModeId` 请求最高刷新率，避免 LTPO 把非游戏应用压到 60Hz。

## 八、仍然成立的两条判断

1. **资源包只改参数，不改算法。** 远程能下发的是数据；解析逻辑、界面、动效一律随 APK。
   原因不是技术做不到，而是"远程可执行代码"等于把信任边界交给仓库之外。
2. **非官方工具的边界**：不登录、不采集、不调用学校私有接口。所有学校数据来自公开页面与
   用户自己导出的文件。
