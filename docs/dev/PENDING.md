# 十、其余（P4）

## 技术栈迁移：Flutter（候选，需你拍板）

**动机**：动效与 UI 材质的上限、开发灵活度与适配性。这不是「哪个语言更好」，
而是**这个应用往后靠什么取胜**的问题 —— 如果重信息的工具属性已经够用，
接下来拼的就是观感与手感。

**先摆一个被忽略的事实**：Compose 并不是做不了材质，`graphicsLayer` + `RenderEffect`
（API 31+）能做模糊与着色器，但**兼容性随系统版本断档**，低版本直接降级。
Flutter 自绘整帧，同一套效果在不同机器上表现一致 —— 这正是「适配性」三个字的含义。

现状规模（2026-10-31 实测，89 文件 18,283 行）：

| 层 | 文件 | 行数 | 占比 |
|---|---|---|---|
| `ui/` | 35 | 10,392 | **57%** |
| `data/` | 24 | 3,927 | 21% |
| `parser/` | 11 | 1,055 | 6% |
| `domain/` | 5 | 793 | 4% |
| `widget/` | 3 | 719 | 4% |
| `util/` + 其它 | 11 | 1,397 | 8% |

结论：**要换的只有 UI 那 57%**。数据、解析、分发、通知、小组件（约 8,000 行）留在原生。

三条路线：A 全量重写（成本最高，单向门）／**B 混合 add-to-app（推荐）**／C 不换。
推荐 B 的理由不是「折中」，而是它把不可逆的部分压到最小 —— 数据层、解析器、小组件一行不动，
做不下去还能一页一页退回来。

分阶段：阶段 0 先把与框架无关的部分做扎实（资源包、解析自检、错误可见，换框架也得有）；
阶段 1 用 add-to-app 只做一个页面（建议资讯卡片，动效最密、逻辑最轻、失败可回退）；
阶段 2 铺开，小组件/通知/解析器保持原生。

**决策门（不达标就不铺开）**：

1. 试点页面冷启动增量 > 400ms → 停，「打开就看课表」的定位撑不住
2. 包体增量 > 8MB → 停，2.8MB 涨到 11MB 会抬高「未知来源安装」的犹豫
3. 单页 MethodChannel 往返 > 20 次 → 重新评估边界，别把原生当数据库用

必须一起解决：小组件仍走 Glance（Flutter 无官方 AppWidget，`updateAll` 时机要重设计）、
通知与闹钟留在原生、双引擎内存要在 4GB 低端机实测。

版本号：架构级变更按规则要动主位，我不自行决定。倾向 `0.40.0` 起（继续 0.x），
`1.0.0` 目前给不出「功能定型」的承诺。

## 课表双指缩放

现状：课表**没有任何滚动容器**，是"整屏自适应"（`cellHeight` 夹 30–64dp、
`columnWidth` 按列数均分），所以不存在放大余地。

- [ ] 先把"整屏自适应"改成"可滚动"，再上 `graphicsLayer` + `transformable`
- [ ] 手势消歧：`HorizontalPager` 吃横向拖动，需"`pointerCount >= 2` 或 `zoom > 1f`
      时才由缩放层消费"，并在 `zoom > 1f` 时关掉 `userScrollEnabled`

- 已知限制：`graphicsLayer` 不改布局，`Text` 的 `maxLines/ellipsis` 不会重新换行，
  放大只是"字变大"而非"看得更多"

# 归档

已发布的实现与历史验收。**只在上面章节需要引用其结论时才回来看**。

## 已发布：0.32.4 字体不随系统缩放

根因：`sp = dp × fontScale` 跟随系统放大，而卡片高度写死 dp，字号变大容器不变就被裁。
修法：固定高度容器内的字号统一走 `fixedSp(v) = (v / fontScale).sp` 反向补偿。
不做：全局禁用 fontScale（会牺牲无障碍设置）。

## 已发布：0.32.4 小组件视觉重做

三态（NEXT / ONGOING / FINISHED）、无边框、圆角 22dp、内边距 14dp、
分钟数 46sp 红色、课名 20sp 粗体。列表 4×2 两行、2×4 三行。
**长期有效的约定**：小组件与资讯卡的视觉改动先出 SVG 草图，参数标在图上，确认后再写代码。

## 已发布：0.33.x–0.35.x 更新通道

- APK 层面没有"不安装"的更新；能免安装的只有内容外置
- 差分包（bsdiff）**不做**：2MB 的包省不了多少，patch 矩阵与回退成本远超收益
- 固定签名是硬前提：debug keystore 按机器生成，CI 每次不同 → 包永远盖不上旧版
- 清单走 `api.github.com`（实时），文件走 CDN（路径带版本号，不可变）：
  **"现在最新是第几版"这件事不能缓存**
- 失败分两类：网络原因不记 `failedVersion`，只有内容原因才拉黑，且 6 小时后允许重试
- 资源包版本号用 `yyyyMMddHHmm`（Long），只升不降，`minAppVersion` 挡旧端
- 两个检查器互不调用，日志分 `[Update]` / `[Pack]`

## 已验证（历史验收）

- **0.27.x**：提醒链、横带半径 28dp、导航岛 36dp、切周动画
- **0.28.0–0.30.4**：详情页高亮、置顶卡开关、5/7 列自适应、电池白名单跳转、调课面板
- **0.30.9**：「我的」页版本号重复与副标题折行
- 一条被证伪的担心：三位数「100」不会出现（剩余 ≥60 分就进位成小时），
  `fontSize = if (top.length > 2) 22.sp` 是死代码，留着当防御
