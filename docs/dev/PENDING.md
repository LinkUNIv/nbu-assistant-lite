# 二、更新链路（0.38.5，P1）

用户反馈「MAA 的更新总是更及时」。查过 MAA 官方文档，差距不在实现复杂度，在四处：

| 维度 | MAA | 我们 |
|---|---|---|
| 检查时机 | 启动 + 每天固定两点（本地 04:00 / 22:00） | 启动 4 秒后 + 前台恢复，间隔 6 小时，**只有开 App 才查** |
| 渠道 | stable / beta 分离 | 已按 `channel` 过滤（0.37.8） |
| 传输 | ETag / Last-Modified 条件请求 | 每次全量拉 releases 列表 + manifest，**两跳** |
| 更新源 | GitHub + 镜像 CDN | 仅 GitHub API，单源 |

## 2.1 条件请求（省流量、降限流风险）

现在是「列表 → manifest」两次全量请求，未鉴权 API 每小时 60 次/IP，多人共用网络时容易撞线。

- [ ] 缓存 `ETag` / `Last-Modified` 到 DataStore，请求带 `If-None-Match` / `If-Modified-Since`
- [ ] 命中 304 直接按「无变化」处理，不解析、不下载
- [ ] 304 也要算作「刚检查过」，否则会每次启动都重试

## 2.2 定时检查（WorkManager）

- [ ] 每日一次 + 启动检查（两条路都留，启动那次解决「刚打开就想看」）
- [ ] 仅在联网时跑；失败退避重试，不要每小时重试
- [ ] 与「更新弹窗」开关联动：关掉只记状态不弹，小红点仍然亮
- [ ] 注意省电策略与厂商后台限制，需真机验证（与第八节前台服务是两件事，别混）

## 2.3 缓存包状态判定抽纯函数

0.37.17 的回归只在一个状态组合下出现，单测与常规手测都碰不到。逐条对照：

| # | 当前版本 | 最新版本 | 缓存包 | 期望 |
|---|---|---|---|---|
| 1 | 3717 | 3717 | 无 | 检查更新 → 已是最新 |
| 2 | 3717 | 3717 | `nbu-lite-3717.apk` | **不出现「可安装」**，启动即清理 |
| 3 | 3717 | 3717 | `nbu-lite-3715.apk` | 同上 |
| 4 | 3715 | 3717 | `nbu-lite-3717.apk` | 显示「可安装」，点一下装 3717 |
| 5 | 3715 | 3717 | 无 | 弹窗（含说明与体积）→ 点下载 |
| 6 | 3717 | 3718 | `nbu-lite-3717.apk` | 显示「发现新版本」→ 点检查 → 弹窗 |
| 7 | 任意 | 任意 | 已交给系统后取消 | 行文案「等待系统安装」，可再点唤起 |

- [ ] 第 2、3、6 条目前只能手测：把 `cachedApk` 判定抽成纯函数（不碰 File/Context）并加单测

## 2.4 明确不抄

**第三方下载镜像**（MirrorChyan 需 CDK，ghproxy 一类不可控）。
sha256 能挡住「下到半截的包」，挡不住「源被整体换掉」—— 后者要靠第二渠道校验签名，我们没有。
若将来国内下载确实频繁失败，再单独评估**自建**静态镜像，而不是接公共代理。

# 三、侧栏液态玻璃与动效（0.38.6，P1）

产品口径已定：**包体不是约束**，最终形态是「功能完整 + 动画精美 + 设计感强」，一百兆上下可以接受。
评估动效只看两件事：**有没有明确的使用场景**、**会不会破坏统一节奏**，不再以「多几兆」为由否决。
参考清单与统一口径见 [`docs/design/MOTION.md`](../design/MOTION.md)。

**前置验证结论（2026-11-11）**：Haze **0.7.3 可编译**（AAR 仅 72KB，内部 `RenderNodeImpl` + 版本门控，
API 31+ 真模糊、以下退化）。Haze 2.x 与 Cloudy 0.7.1 依赖 kotlin-stdlib 2.4，Kotlin 1.9 读不了其元数据，排除。
0.37.19 已升 Kotlin 2.0.21 / Compose 1.7.3，**这一次要重新核一遍能否上 Haze 2.x**。

**形态已定（2026-11-10）：方案 A，保留右侧常驻侧栏，只换质感与动效。**
项目没有 bottomBar，导航是 56dp 右侧胶囊，内容让位 64dp。

- [ ] 侧栏玻璃底：内容区标 `hazeSource`，栏用模糊消费；API < 31 或库不可用退亚克力
- [ ] 选中项滑动胶囊：`Animatable` + `graphicsLayer.translationY`，`spring(0.8, 400)`
- [ ] 图标 `scale` 1.0 → 1.08 与胶囊同弹簧；选中色 `tween(120)`
- [ ] 按压反馈：`scale 0.94` + 圆角收紧，松手回弹
- [ ] **[目视]** 深/浅两套截图对照，模糊区与内容区在滚动时不脱层

动效统一（与上条同一版，别拆开验）：

- [ ] 把散落的 `tween(150/180/220)` 收敛到四档：120 / 180 / 240 / 300ms

# 五、课表截图 OCR（P2，不占版本）

课表导入的第三条路。**与已落地的签到码识别是两条线，别混为一谈**：

| | 签到码识别（已做） | 课表截图 OCR（未做） |
|---|---|---|
| 目标 | 从一帧画面里找 4 位数字 | 从一张截图里还原整张课表 |
| 输入 | 相机实时流 | 相册图片或截屏 |
| 难点 | 颜色定位 + 倒计时内出结果 | **表格结构还原** |
| 输出 | 一个字符串 | 结构化课表 |

底座已有：`com.google.mlkit:text-recognition-chinese:16.0.1` 是 bundled 版，模型随包走、离线可用，

- [ ] 复用 `SignImagePreprocessor` 的降采样与增强思路，但**不要复用颜色定位** ——
      课表没有「蓝色环境里的黄块」这种特征，按颜色找必然找错
- [ ] 直接吃 ML Kit 的 `Text.TextBlock` 全量结果，交给结构还原
- [ ] **结构还原是唯一真正的难点**：合并单元格、节次列、`1-16周(单)` 注记、连堂课。
      可复用 `parser/GridParser`、`FieldExtractor` 已有的周次与节次正则
- [ ] 必须有**预览校正**：识别 → 可编辑结果 → 用户确认 → 入库。跳过这步，错一个字比手动输入更烦

# 已决（不做 / 暂缓）

| 项 | 结论 | 理由 |
|---|---|---|
| 系统通知推送更新 | **不做** | 渠道关闭、免打扰、权限被拒一串分支，打开频率够用 |
| 「本次更新内容」独立入口 | **不做** | 与「更新日志」页重复 |
| 资讯卡片底色用主题色渐变 | **不做** | 深色下几乎不可见，浅色下容易发脏 |
| 卡片名言（`assets/quotes.json`） | **不做** | 课表工具的核心价值是「快」，名言拖慢扫读 |
| 7 列课程名截字阈值 | **待真机对比** | `nameLimit` 只在列宽 < 34dp 触发，7 列约 44dp 不触发；提到 40dp 能少折两行，但代价是 5 列不截、7 列截，两档观感不一致 |
| 差分包（bsdiff） | **不做** | 2MB 的包省不了多少，patch 矩阵与回退成本远超收益 |
| 第三方下载镜像 | **不做** | sha256 挡不住「源被整体换掉」，需第二渠道验签，我们没有 |

已决项不进路线图。要重启任何一条，先把「为什么当初否掉」推翻。

## 工程约定（长期有效）

- **小组件与资讯卡的视觉改动先出 SVG 草图**，把内边距/字号/圆角/色值标在图上，确认后再写代码。
  改的是数值不是代码，用编译验证数值效率极低。
- **固定签名是硬前提**：debug keystore 按机器生成，CI 每次不同 → 包永远盖不上旧版。
  所有版本共用 `619b80a7…9538`，换密钥等于所有人卸载重装。
- **「现在最新是第几版」不能缓存**：清单走 `api.github.com`（实时），文件走 CDN（路径带版本号，不可变）。
- **资源包版本号 `yyyyMMddHHmm`，只升不降**；`minAppVersion` 挡旧端；失败分两类
  —— 网络原因不记 `failedVersion`，只有内容原因才拉黑且 6 小时后允许重试。
- 两个检查器互不调用，日志分 `[Update]` / `[Pack]`。
- **中文路径下跑单测全红**（5 类 `initializationError`）：`android.overridePathCheck=true`
  只绕 AGP 检查，绕不过 test worker 的类加载。出包一律在 ASCII 副本里做。
- **同一 tag 别发两次 release**：已发布的空 release 会锁死 tag，删不掉也重建不了，只能作废版本号。
  workflow 已有并发组 + 幂等检查 + 发布后自检三道闸。
- **固定高度容器内的字号要反向补偿**：`fixedSp(v) = (v / fontScale).sp`，
  否则系统放大字号会把内容裁掉（0.32.4）。不做全局禁用 fontScale。
