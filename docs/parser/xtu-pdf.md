# 湘潭大学课表（PDF）取词规则

样本：`(2026-2027-1)课表.pdf`，2 页，文本层可提取（**不是扫描件，不需要 OCR**）。
机器可读版本见同目录 [`xtu-pdf-rules.json`](xtu-pdf-rules.json)。

## 一、为什么不能"按文本顺序切"

把 PDF 直接导出成文本，得到的是一串没有星期归属的碎片：

```
政治经济学
(1-2节)2-3周/校区:校本部
/场地:信息科技大楼北-
401/教师:肖薇薇/考核方式
```

**"星期几"不在单元格文字里**，它只由列位置决定。所以必须取带坐标的文本，按坐标归列。

## 二、三条定位规则

### 1. 列：以表头为锚

| 表头 | 星期一 … 星期日 |
|---|---|
| 锚点 | 表头文字的 x 坐标 |
| 列宽 | `(x_日 - x_一) / 6`，实测 103.9pt |
| 归属 | 片段 x 落在 `[left + i*step, left + (i+1)*step)` 即第 i 列 |

表头居中、正文左对齐，所以列的左边界要回退半个列宽，不能直接用表头 x。

### 2. 行：同列纵向聚类，**不要用节次数字切**

这是第一版踩的坑。页面上有 1…12 的节次数字，看着像行号，但：

- 一门课写的是 `(1-2节)`、`(3-4节)`，**一个单元格跨两行**
- 单元格在行内**垂直居中**，它的第一行往往在节次数字之上

按数字切，单元格必然被劈成两半——实测 44 个碎片被切成 26 段噪声。

正确做法：同一列内，相邻片段的 y 差 **> 14pt** 才算新单元格。实测行距是 12.0pt，单元格之间的最小间隔是 15.5pt，14 是安全阈值。

### 3. 页：表头过滤必须逐页判断

第 2 页是**续表**，没有表头，内容直接从页顶开始。若用固定 y 阈值过滤表头，整页内容会被丢掉——第一版就是这样丢了「思想道德与法治 9-11节 12-15周」。

规则：仅当**本页存在「星期X」表头**时，才丢弃表头以上的片段。

## 三、单元格字段

拼接同一单元格的多行片段时**不加分隔符**：中文换行会把词语切断（`信息科技大楼北-` + `401`），加了空格反而错。

```
课程名(起节-止节节)周次/校区:校本部/场地:逸夫楼-102/教师:熊振亚/考核方式:考查/学分:3
```

| 字段 | 规则 |
|---|---|
| 课程名 | `(` 之前的部分，保留全角括号与罗马数字（`大学外语1（全）`、`管理学Ⅱ`） |
| 节次 | `(N-M节)` |
| 校区 | `/校区:` 到下一个 `/` |
| 场地 | `/场地:` 到下一个 `/`，形如 `信息科技大楼北-401`、`逸夫楼四阶` |
| 教师 | `/教师:` 到下一个 `/`，可能多人 |
| 考核方式 | `考试` / `考查` / `未安排` |
| 学分 | 小数，`2` 与 `2.5` 都存在 |

## 四、周次语法

| 写法 | 含义 |
|---|---|
| `2-3周` | 第 2、3 周 |
| `4-5周,10-15周` | 逗号分隔多段 |
| `第16周` | 单周，带「第」 |
| `3-4周,10-11周,13-17周(单),18周` | **单双周必须展开**：13/15/17 |
| `第2周` | 与 `2周` 等价 |

单双周按**周次奇偶**过滤，不是按区间内第几个。这一条漏了会少排课时（实测「高等数学习题课1」从 8 节变成 5 节）。

## 五、噪声

| 类型 | 处理 |
|---|---|
| 学时图例（`调查学时 : 线上学时 …`） | 丢弃 |
| `打印时间:2026-11-10` | 丢弃 |
| 页脚 `实践课程：军训陈海霞(共3周)/7-9周` | **不占格子**：有周次，没有节次与星期，只能记成课程标签 |
| 页脚 `其他课程：…` | 同上 |

页脚这些课如果当成正常课程排进去，会在课表上凭空多出几格。

## 六、校验

| # | 断言 | 本次结果 |
|---|---|---|
| 1 | 单元格数 = 全文 `(数字-数字节)` 出现次数 | 26 = 26 |
| 2 | 解析后未匹配条目 = 0 | 0 |
| 3 | 周次展开非空、上限 ≤ 20 | 通过 |
| 4 | 抽样人工核对 | 政治经济学 周一 1-2 节两段（2-3 周 @北-401、4-15 周 @北-103）与 PDF 一致 |

## 七、接入位置

`TimetableParser.parseFile()` 目前只接受 `.xlsx / .xlsm / .docx / .doc`，**没有 PDF 分支**。要在应用内直接用这份规则，需要：

1. 引入一个能给出**文本坐标**的 PDF 库（Android 侧常用 PdfBox-Android）
2. 把本文的列/行/页三条规则实现成一个 `XtuPdfParser`
3. 按第六节的三条断言写单测（用本地样本，**样本含学号，不入库**）

这三步属于 PENDING 的「0.38.0 课表解析词典外置」与「0.40.0 多校适配」，不在当前版本范围内。
在此之前，这份规则的价值是：**下次拿到同一模板的 PDF，按它实现即可，不用重新试错**。
